# Decision Log

Architectural and tooling decisions, newest at the bottom. Each entry records the
decision, why, and what was rejected - so the next engineer doesn't re-litigate.

---

## D1. Hindsight runs locally (pip install), not Docker

**Decision:** Run `hindsight-api-slim[embedded-db,local-onnx]` 0.10.1 as a local
Windows process via `scripts/start-hindsight.sh`, with the pg0 embedded Postgres,
the ONNX embedder (`intfloat/multilingual-e5-small`) and the FlashRank reranker.

**Why:** The Docker daemon is not running on this machine and `docker compose up`
cannot be exercised locally. The pip path is fully supported on Windows and was
proven end-to-end. `docker-compose.yml` still ships for environments with Docker.

**Rejected:** Docker (unverifiable here), Hindsight Cloud (needs an API key we do
not have), SQLite backend for Hindsight itself (the installed version exposes
Postgres only via pg0-embedded).

---

## D2. Hindsight LLM backend is local Ollama (`llama3.2:latest`)

**Decision:** `HINDSIGHT_API_LLM_PROVIDER=ollama`, model `llama3.2:latest`,
`HINDSIGHT_API_LLM_BASE_URL=http://127.0.0.1:11434/v1`.

**Why:** No `GROQ_API_KEY` is present in the environment, and Hindsight's fact
extraction wants ~65k output tokens - far beyond Groq's free tier (~8k TPM).
Ollama is running locally, has no token limits, and `llama3.2` supports tools.

**Rejected:** Groq as the Hindsight extraction backend (free tier TPM far below
what extraction consumes). Groq remains the *documented* primary for the app's
own LLM tasks the moment a key exists - `config/llm.yaml` already lists
`openai/gpt-oss-120b` / `qwen/qwen3-32b` as the Groq chain.

---

## D3. Windows console encoding kills the server banner - UTF-8 forced

**Decision:** `scripts/start-hindsight.sh` exports `PYTHONUTF8=1` and
`PYTHONIOENCODING=utf-8` before launching.

**Why:** The server's ASCII-art banner uses block characters (U+2580 block
elements) that cp1252 cannot encode; the process died in `banner.py` before ever
binding port 8888. Redirected stdout inherits the console encoding.

---

## D4. First-run model init timeout raised to 1800s

**Decision:** `HINDSIGHT_API_MODEL_INIT_TIMEOUT=1800` in the launcher script.

**Why:** The first boot downloads the ONNX embedder (~2min) and the FlashRank
reranker; the 300s default aborted startup mid-download with "Model/connection
initialization did not complete within 300s".

---

## D5. Hindsight API surface - verified by live smoke test, not assumed

**Decision:** `backend/memory/hindsight_client.py` is the single module allowed
to call Hindsight, and its shape is fixed by a live smoke test
(`scripts/smoke.py hindsight`), not by docs guesses.

**Verified findings encoded there:**
* `metadata` on a retained item **must be `Dict[str, str]`** - ints/bools raise
  pydantic `ValidationError`; `stringify_metadata()` coerces everywhere.
* Recall results carry **`scores = {final, reranker, semantic, keyword}`**; the
  pipeline confidence uses `scores.final`.
* Every memory is tagged `bank:nevertwice` + `kind:<unit>`; recall scopes with
  `tags_match` (verified: tag-filtered recall returns 6/6 with the service tag,
  0 with exact-empty scope) so feedback and incidents are isolatable.
* `reflect` accepts `response_schema` for structured output; `include_facts=True`
  returns `based_on` evidence.
* Inside FastAPI handlers, only the `a*` async variants may be used - the sync
  client spins its own loop and dies with "This event loop is already running"
  (caught live in the first `/api/health` test).

---

## D6. Verdicts: Hindsight `reflect` produces the reasoning; the app computes the verdict numbers

**Decision:** The analysis pipeline calls Hindsight `reflect` with a
`response_schema` to get grounded reasoning + `based_on` evidence, and the
*application* computes `confidence`, `evidence_count` and
`supporting_memory_ids` in Python from real recall results.

**Why:** Confidence asked from an LLM is a guess (rule 4). Confidence computed
from retrieval scores, evidence count and feedback agreement is auditable and
reproducible, and it makes the feedback loop's effect measurable.

**Rejected:** LLM-over-evidence in our own prompt for the verdict - `reflect`
already does retrieval + reasoning in one auditable step and exposes its
evidence; duplicating it would blur which system produced the answer.

---

## D7. Sources are discovered, not typed

**Decision:** `config/sources.yaml` is generated by
`scripts/discover_sources.py` from the danluu/post-mortems index, then curated by
a deterministic selection policy (`max_total: 30`, `max_per_org: 3`).

**Why:** The brief forbids invented data. 105 real URLs were harvested from the
index (AWS, Cloudflare, GitHub, Google Cloud, CircleCI, ...); the selection
policy keeps the org mix balanced without hand-picking.

---

## D8. The evaluation must survive contact with a shared memory bank

**Decision:** The eval harness verifies split integrity *before* scoring
(`GET /api/eval/split-check`), purges leaked held-out documents by their
deterministic document IDs when found, chooses the feedback warm-up slice
**per incident**, and excludes warm-up incidents from scoring in *every*
condition so A/B/C always compare the identical case set.

**Why:** Discovered by the harness itself during the build: (1) the first
ingestion predated the split-default fix and all 9 held-out incidents sat in
the production bank - the live split-check caught it and
`scripts/purge_heldout_from_bank.py` removed 30 documents; (2) warm-up sliced
by case order let `i2-risky`'s good_catch feedback recall when scoring sibling
cases of the same incident - visible in run 4 where C flagged the safe siblings
that B correctly passed. Per-incident warm-up removes the leak structurally,
not statistically.

**Consequence:** A "worse" number in the table is always interpretable: the
small-sample guard downgrading on thin recall, a model lapse, or a genuinely
hard case - each one inspectable per-item in `eval_items`, never averaged away.

---

## D9. Local-model realities are configuration, not code

**Decision:** Three live-verified operational facts are encoded in
`scripts/start-hindsight.sh` and `.env.example` rather than discovered anew by
every demo: reflect's built-in LLM deadline (30 s) is far under what
`qwen2.5:7b` on CPU needs, so `HINDSIGHT_API_LLM_TIMEOUT=900`; the Hindsight
sync client gets a fresh instance per call because its cached aiohttp pool is
bound to whichever event loop created it (worker threads die with "Timeout
context manager should be used inside a task"); and model JSON that puts
literal newlines inside strings is parsed with `strict=False` before a
model-chain fallback is burned.

**Why:** Each was a real, reproduced failure during the eval runs (condition C
dying on Hindsight 500s, condition B dying on loop-bound pools, safe-case
generation failing on diffs-in-JSON). They are properties of the local
toolchain, so they belong in the ops layer; the product code stays
toolchain-agnostic.

**Consequence:** After these fixes run 5 completed with A/B/C scored on the
same 6-case set: accuracy 0.33 -> 0.60 -> 0.80, F1 0.0 -> 0.50 -> 0.86, zero
false positives in B and C - with every miss still inspectable.
